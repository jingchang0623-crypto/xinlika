# 心力卡 0.4.0：自动事件、跨对话主题与 Agent

后续真实验证：见[0.4.1 真实视频会议闭环](xinlika-real-loop-2026-10-21.md)。自动校时、录制时间、重点与问答已获得新真机证据，但用户标注同一议题的两次录音仍漏关联；本页的虚构文字模型验收不能替代该真实未通过项。

这是实际接入现有 Mac 应用和本机服务的版本。原始录音、既有转写与纠正记录保留，没有发布云服务或提交 Git。

## 已接通

持续采集仍按原方案封批，ASR 不变。新的语义结果不是批次列表：

1. 新转写在已有 LangGraph 抽取调用中同时生成事件；相邻批次可延续同一件事，话题切换才拆分。旧转写通过持久任务补整理，不重新调用 ASR。
2. 模型看到已有主题和未归类的历史事件，可以用不同措辞关联同一事项，也能回关联先前尚未归类的讨论。明确持续事项自动建立主题，不要求用户先建项目。
3. Agent 检索事件、主题、原文和已有记忆，综合回答并返回版本引用。普通现场记录无需逐条确认；用户纠正优先于旧抽取。背景/未知来源不自动成为用户个人经历。
4. 纠正原文立即使相关事件、主题和旧回答失效，随后从当前原文重建，不重新转写音频。跨批次事件和相关主题的其他来源也会重新关联，避免只改局部留下旧结论。

沿用既有 LangGraph、SQLite Checkpointer、OpenAI SDK、Pydantic 与 voxgate。新增的是 SQLite 产品数据和采集适配逻辑，没有自建第二个 Agent 框架或叠加多套记忆库。Omi 的事件/证据/建议路径作为架构依据；本轮没有整体部署或直接移植 Omi/OpenMuse。

## 界面

主导航收敛为“今天、主题、Agent”，设备入口置底。短事件只呈现标题，较长事件显示两行摘要；详情再查看原文、原声与纠正。重叠重点保留独立处理结果，在普通事件上显示重点标记和详情入口，首页不重复堆两张相同内容。原始会话、记忆字段和处理任务放到设备页的次级入口。

不再展示普通事实审核队列，也不以确认数量为产品进度。已有旧回答因依据变化失效时标明更新，不能继续当作当前答案。

用户提供的五张心力球截图已查看并保存在忽略的私有目录。采用了短/长事件密度差异，以及采集与整理进度分离；没有复制其私人内容、会员页面或把功能介绍卡当作真实主动洞察。设备页当前显示“最近收到音频”和“最近完成整理”，不是未经证明的连续覆盖终点。

## 录制时间修正

用户指出事件时间不应使用处理时间。这一问题已同时修正后端、历史来源和界面：

- 事件展示和排序只使用录制证据。取消以 created_at/导入时间作为事件时间的回退；未知就显示“录制时间未知”，排在已知时间之后。
- 本次实时录音以主机采集起点及音频字节偏移估算批次录制时间，界面标“约”；不冒称采样级校时。
- 两段历史选段重新核对了原文件哈希、原文件内选段字节、再次导入的范围，以及批次偏移。恢复文件名中的设备本地时间，明确显示“设备时间”。设备时钟未校准，因此没有把它写成已校准的绝对发生时间，也不据此推算承诺日期。
- 新导入支持保留原始录音来源；从其他选段文件导入时，必须与指定原录音的字节范围一致。提供已知录制时间时也会计入选段和批次偏移。
- Agent 获得同一时间来源和精度，不能因为今天处理，就回答事情发生在今天。

事件内仍是批次起点/来源锚点，不是词级时间对齐。同一批次中的多个事件可能有相同时间；交错发言的来源区间可能包含上下文，API 保留 span_envelope 精度，未宣称无重叠或逐字准确。

## 实测与检查

| 项目 | 结果与范围 |
|---|---|
| Python 自动检查 | 44 项通过，覆盖 HTTP、任务恢复、事件延续、主题关联、重点、纠正、精确来源选择及录制时间；模型/ASR 替身不计入真实准确率 |

| 真实模型隔离验收 | 8 项通过：同事件跨批次、跨对话主题、无需确认问答、零手工确认、旧答案失效、更正后日期、任务恢复和重启持久化。采用虚构文字与实际配置模型，不是实际语音准确率 |
| 已有真实语音转写 | 10 个语义整理任务全部完成，形成 7 个独立语义结果、2 个主题，人工确认数量仍为 0。普通时间线将重叠重点折叠为标记 |
| 原生 Mac | 实际查看深色与浅色、主题详情、原文/原声入口、纠正表单打开取消；恢复跟随系统。历史事件显示设备时间，实时事件显示录制估计 |

真实模型首次暴露了未建主题/未回关联问题；后续发现改写原句、散选原文编号及重点被拆成多个事件的问题。均据实修复，失败记录留在私有验收目录，没有把第一次结果改成通过。原文选择现在从原始片段编号恢复，必要时明确包含交错上下文，避免用模糊匹配伪造证据；无效输出有界重试，磁盘保存失败则复用检查点。

脱敏结果：[validation](validation/xinlika-semantic-2026-10-21/result.json)。真实转写、模型正文、原声、截图和凭据都留在被忽略的 .build。

## 使用与限制

运行 python3 scripts/run-heartball-lab.py，打开 .build/心力卡.app。现有本机配置继续使用；打开应用不会自动启动录音。此次没有新增硬件操作或调用 ASR。

当前仍是本机可运行版本：没有新增云部署、外部 MCP/IM 接入或全天后台稳定性验收。主题上下文有数量上限；自动关联、说话人判断和总结仍可能出错。跨对话闭环已用真实模型验收，真实项目的长期关联质量、耗时/成本分位数和多人逐字准确率仍需持续实测。
