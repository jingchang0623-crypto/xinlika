## 实际处理与切换

沿用现有手机上传、voxgate ASR、共享 SQLite 权威账本及设备身份。新服务先提供上传与同步接口，再等待旧 worker 释放唯一处理锁；旧进程排空后停止，反向代理切换到新服务。保留旧镜像和配置供回退，没有给录音卡发送开始、继续或停止命令，没有重装或调试启动手机 App。初始化采样出现过一次约 5.91 秒状态请求及 BrokenPipe，不能据此宣称所有接口零中断。

处理边界在持久账本中登记已有音频批次、重点与来源版本。启用前已存在但晚生成文本的批次仍属于旧基线，不因部署重扫；新增来源和用户纠正的新版本进入 v6。核对基线 **2,050 个已完成 ASR 任务**，状态与尝试次数未变；原 ASR 正文、分段未变，已结束历史会话未变。没有重跑历史 ASR，也没有重复播放旧留出集调提示词。

实际新来源已经经过增量提炼、滚动整理和主题复核。手机和 Mac 都显示了真实事件与录制时刻；其中一次 20:26 完成整理的事件仍显示 **20:21**，不是处理时间。现有模型接口与权限沿用；Harness² 优化器没有放进在线录音请求。

## 纠正同步与现场发现的修复

真机验证中发现：较早原句被纠正时，原事件已由较晚来源续写，普通的时间窗口会漏掉该事件，导致纠正内容单独变成小事件。修复在宿主上下文层：仅沿明确的用户纠正血缘召回原事件的兄弟来源，标明这是原录制内容的更新，保留原时间；普通迟到 ASR 仍不能看到未来事件。v6 Skill 内容未改。

修复在当前真实来源的隔离副本上做了三次开发复核，包括一次失败，共 4 次模型请求、29,974 tokens；不是新的独立盲测。上线后，真实纠正曾续回同一事件并保留 20:21 时刻。后续滚动整理可继续归入更完整的取件事件，不能承诺所有纠正永远保持同一事件编号。

实际操作完成了 Mac 编辑、手机事件展示，以及手机编辑、Mac 原句读取和恢复。测试仅改变标点，已恢复原文；两端设备凭据读取到相同的恢复正文、事件和主题，旧版本保留，过期版本写入曾返回 409。两端主题页也已实际查看。镜像窗口间歇失效，最后一次恢复正文在手机 UI 的再次打开未完成，不能用 API 核对冒充这个 UI 步骤。

## 核对结果与未完成项

66 项相关技术测试通过，Mac 构建和真实云端日数据的 Swift 解码通过。最后一次全量任务检查为 20 个 native 任务完成、无任务错误、无待处理队列。55 次模型来源版本核对没有正文或录制时间差异。

最终投影核对覆盖 95 个原文片段：无缺失、无过期范围，但 **1 个片段同时保留为内部 fragment 并属于一个活动事件**。这不代表首页存在两个事件，却使唯一分配审计未完全通过，尚需修复；不能沿用较早快照的零重复结果宣称最终通过。界面仍有部分含糊、低价值卡片，全天首页准入质量也未全面验收。
