# 心力球：转写、独立重点与 Personal Agent 的第一条闭环

> 后续交付见 [心力卡 0.4.0](xinlika-semantic-workspace-2026-10-21.md)：事件、主题、问答与录制时间修正已接入。本文保留此前阶段证据。


日期：2026-10-21。已在原生 Mac App 和本机服务中贯通持续采集、转写、独立重点整理、可确认的跨对话记忆、主动反馈、用户纠正和记忆查询。没有切换既有深脑生产路由，没有部署云服务器；本轮交付是可运行的单用户版本，iOS 后台与全天候产品验收仍未完成。

## 实际复用的组件

沿用用户指定的 语音调研会话（私有会话，不随公开仓库分发） 中已经运行的 voxgate 服务和 15 秒内部分段补丁，没有重新编写输入法协议。持续录音按默认 60 秒封批，服务允许 60–300 秒；重点开始／结束会提前封软件批次，不停止硬件。

新增处理层实际采用 **LangGraph + SQLite Checkpointer** 编排“抽取→保存→评估”和记忆查询。保存失败后可从节点检查点恢复，复用已经完成的抽取。**OpenAI Python SDK** 调用兼容转写与模型 API，**Pydantic** 校验结构；本次文本模型实际使用用户提供接口中的 `intern-s2`。SDK 名称不意味着本轮调用了 OpenAI 云端。

Omi 的依据版本、到期复核、纠正失效，以及 OpenMuse 的持久任务／租约思路，落入本项目的业务账本；没有声称已部署两套完整开源产品。组件版本、许可证与复用边界见 [第三方组件清单](heartball-third-party-components.md)。直接依赖及完整安装锁定分别为 `requirements-heartball.txt`、`requirements-heartball.lock`。

## 使用方式

当前已配置并运行，原生 App 为 `.build/HeartballLab.app`。在项目根目录可重新打开：

```bash
python3 scripts/run-heartball-lab.py --skip-build
```

新机器首次准备需要 Python 3.11+，以及已有 CB08 工具链和 FFmpeg：

```bash
python3.11 -m venv .build/heartball-agent-env
.build/heartball-agent-env/bin/python -m pip install -r requirements-heartball.lock
python3 scripts/run-heartball-lab.py --device YOUR_DEVICE_UUID --processing-config /path/to/private-processing.json
```

私有配置示例（凭据只放独立私有文件，不写入仓库）：

```json
{
  "voxgate_config": "/absolute/private/path/to/voxgate/config.json",
  "model": {
    "base_url": "https://your-compatible-model.example/v1",
    "model": "your-model-id",
    "api_key_file": "/absolute/private/path/to/model-api-key",
    "extra_body": {}
  }
}
```

当前本机配置、用户提供的模型密钥、数据库、检查点、原声与正文均在私有 `.build/heartball-lab`。语音继续调用本机 voxgate；它会把音频送到既有豆包研究后端。文本发送到用户提供的模型接口。外部 tracing 显式关闭，未上传长测原始证据或整张录音卡。

操作路径：

1. 在 App 选择是否“转写并整理本次录音”，标明现场对话、背景播放或来源尚未确认，再明确开启持续记录。打开 App 不会自动录音。
2. 随时开始／结束重点。重点复用同一流的转写，单独产生整理结果；全局结束才保存硬件录音。关闭窗口不等于停止采集，实验入口单次最长 30 分钟。
3. 对话整理、原始转写和原声按批次可回看。重点与普通批次分别展示。旧重点若位于批次内部，只能标为“包含边界上下文”，不伪造词级裁剪；新重点在起止处封批。
4. 现场对话的事实与承诺先作为候选，确认后才进入记忆。可改负责人、内容和日期，拒绝错误归属、标记完成；可纠正转写或更改来源分类。
5. 用“查询记忆”读取已确认的状态。回答引用具体记忆版本；纠正后旧回答会标为过期。模型输出的依据必须来自当前记忆，不读取未确认候选当作个人事实。

真实样本当前均未由本次开发自动确认。界面中的整理是待核对的模型结果，不是准确率已经通过。

## 处理与记忆契约

每个采集会话有独立的语音／文本处理授权，启动重试不能改变既有会话的处理范围。未授权历史批次保持阻塞；新会话的处理设置先落盘，再启动硬件。任务区分音频转写、持续整理、重点整理、文字修订和记忆查询；租约恢复及有限重试复用同一身份。模型鉴权或额度错误进入明确阻塞状态，不无限重试。

ASR 返回先持久保存，再建立理解任务；同一音频哈希复用转写，抽取失败不重新识别。重点引用已封批的范围并单独整理，复用普通流的事实，避免同一声音生成两份承诺。完整卡上文件用于归档与缺口证据；极短缺尾进入上下文核对任务，不单独识别后猜词拼接。

模型引用必须逐字出现在输入中。缺少可定位引文的候选被排除，原始模型响应保留在私有证据，整理卡显示未通过引文校验的提示。存在引文只证明可追溯，不保证转写、人物归属或推断正确，因此其余候选仍需用户确认。未知来源和背景播放可以整理，不产生个人事实候选。

历史样本的发生时间保持未知，不用导入日解释“明天”。新采集使用主机接收时间作近似时间锚点，不把设备文件名当准确时钟。相对日期和负责人依然显示为可核对字段。

纠正保留前后版本和幂等回执；依赖旧版本的建议、回答会失效。纠正原文只重新整理文字，不再转写原声。替代已有记忆需核对被替代的版本，防止慢模型覆盖用户刚完成的修改。查询优先使用纠正后的负责人、日期与状态，原有描述不覆盖这些字段；清空日期后不从旧文字重新猜回。

主动反馈由新整理事件和后台计时评估唤醒，首轮规则覆盖待确认承诺／依赖、已确认承诺到期、同项目跨对话的依赖与交付日期冲突。普通事实保持安静，不逐条发卡。提醒有依据、去重身份和状态复核，支持已完成、忽略及少提醒这类事。当前反馈在 App 内展示，没有接入系统推送、外部消息或自动工具执行；这不是通用自主规划器。

## 真实多人音频与新采集结果

复用用户确认过的两份多人选段，各选既有 300 秒快照的前 120 秒，没有扩大到整份历史文件。第一份另设选段内 20–90 秒的重点：六个批次完成转写，六份持续整理及一份独立重点结果完成。识别切段敏感性尚未解决，不能把此结果当成多人噪声／漏词准确率验收。

新一轮真机通过原生界面开启、重点开始／结束和全局保存，结果如下：

| 项目 | 实测 |
|---|---|
| 卡上完整录音 | `note20261021-120153.opus`，317,400 字节，158.70 秒 |
| 实时编码音频 | 317,280 字节，158.64 秒；全量唯一匹配卡上起始范围 |
| 未实时收到 | 卡上最后 120 字节／60ms，完整归档保留；未宣称零丢样 |
| 封批 | 19.28、60、47.60、31.76 秒，共四批 |
| 重点 | 107.60 秒，跨两个批次，独立整理，复用转写 |
| 实时调度证据 | 全局仍在录制、尚无结束时间时，三批语音请求已返回、重点处理任务已完成；本次现场返回空文字 |
| 硬件命令 | 开始 1 次、全局保存 1 次；重点操作期间没有硬件命令 |
| 传输／落盘 | 无断连、无物理文件变化、队列丢弃 0，严格解码通过 |
| 来源边界 | 本次新测试标为未知，不建立个人事实 |

这是新采集与语音服务并行运行的真机调度证据，不是把历史回放伪称为实时口述测试。**这份新录音没有返回可用文字，因此不能作为现场语音内容识别或有意义总结通过的证据。** 已增加空文字状态：保留原声、显示暂无可用转写、跳过模型及个人事实，不生成“无内容”的伪总结。真实内容处理的正向证据包括上述历史多人选段及下方随后完成的实时口述试次。

随后用户参与实时口述正向验证：不照读提示稿，而是自由口述，用户报告说完后只结束软件重点，保持硬件继续录制。全局仍为录制状态且没有结束时间时，41.28 秒重点已返回 80 字非空转写并完成独立整理；用户确认所展示的几个识别片段与刚才所说**基本一致，是本人刚才所说**。因此补上了本人现场语音的正向内容证据，不再只依赖历史回放或空任务调度。

本次口述完整卡上文件 `note20261021-121419.opus` 为 189,720 字节／94.86 秒，实时收到 189,600 字节／94.80 秒，唯一完整匹配卡上起始范围，卡上末 120 字节／60ms 未实时收到而由完整归档保留。无断连、无物理文件变化、队列丢弃 0、严格解码通过；同样只有全局开始／保存各一次，重点操作不发硬件命令。测试内容没有建立个人事实。用户的基本一致确认是定性验收，不是逐字稿，也没有计算 CER/WER；提示关键词未命中不能作为错误率，因为用户明确没有照读。

编码字节比对不等于麦克风采样连续或口述逐字完整。重点边界仍是收到音频包的位置，尚未校准物理操作到 ADC 的精确延迟。

首次并发试次暴露了共享 SQLite 连接的无锁读访问，导致业务监控线程退出；原始 BLE 接收仍落盘。已保存该专用录音、保留日志与完整卡上参考，未将它算为实时处理通过。修复统一访问锁，并增加并发回归；处理权限也移到启动硬件之前持久化。上表是修复后的另一份新录音。故障样本未发 ASR、未删除，后续不静默接管旧 PID 或重启录音。

## Personal Agent 闭环的验证范围

另在隔离数据库中使用**虚构的两次项目对话＋真实模型 API**验收，测试数据没有写入用户的个人账本：

- 第一次对话提取并经测试操作明确确认依赖；第二次对话读到已有记忆，提取交付承诺，后台产生跨对话时间冲突建议，无需再提问。
- 纠正负责人和截止日期后，旧冲突建议失效；重复提交反馈不增加修订。真实模型后续回答使用更正后的人物与日期，并引用更正版本。
- 模拟到期时间触发跟进；标记完成后不再生成旧提醒。完成态服务／账本重开，记忆、反馈和建议保持一致。

中间验收曾发现“引用新版本却回答旧日期”：旧描述中的日期覆盖了纠正字段。已修复查询优先级，并把最终验收扩大为检查实际回答中的负责人、日期和引用，不能只凭引用版本正确就通过。早期结果保留为诊断，最终以更严格的结果为准。

回归覆盖存储 9 项、旧采集 API 3 项、处理／来源／恢复／并发及空转写 14 项、新 Agent API 4 项；原生目标构建及共享 Swift 客户端读取、原声 WAV 核对通过。LangGraph 模拟保存失败后恢复的测试确认不会再次调用抽取模型。真实界面完成新录音的全流程；纠正与主动状态的语义验收使用上述隔离模型测试和 HTTP 测试，未自动确认真实用户录音中的候选。

脱敏实测、故障与持久化证据见 [results.json](validation/heartball-processing-2026-10-21/results.json)。原始音频、文字、检查点与请求结果只在 `.build`，没有 Git 提交、推送或外部发布。

最终构建、签名和共享 Swift 客户端读取通过，完成态服务重启及新增采集后，已有转写、文档、任务、候选和建议逐项不变，识别缓存没有重传。原生界面已实测采集全流程和处理结果展示；最后重新绑定最终构建的 UI 自动化工具连续超时，最终视觉重验未完成，不能冒充所有表单都做过真机点击验收。后续补了同内容快照不重复刷新界面的优化，单独构建验证。

## 仍需推进的范围

真实多人／噪声 ASR 准确率、说话人归属、跨切段漏词仍待人工参考稿和对齐验收；现有 voxgate 15 秒硬切不是最终生产方案。长时断连修复、正在录制时服务崩溃的安全恢复、iOS 锁屏／后台、全天续航与硬件 VAD 也未完成。机身保存键仍会全局停止，App 重点入口已经可用；不能称为硬件无中断标记键。

当前为单用户本机服务，处理需该服务继续运行；不是手机或云端正式发布。主动反馈先覆盖上述少量可核对规则，尚无通用目标规划、复杂语义冲突识别或外部执行。下一阶段应结合用户实际确认／纠正评估这些反馈是否有用，并继续提高中文真实音频质量，而不是把所有候选自动塞进长期记忆。
