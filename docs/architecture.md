# 心力卡的产品与实现模型

```mermaid
flowchart LR
  A[采集适配器] --> B[不可变批次与原声]
  B --> C[ASR 与声音旁路]
  C --> D[有原句与版本的文档]
  D --> E[事项 / 活动 / 跨对话主题]
  E --> F[问答 / Personal Agent]
  F --> G[少量有依据的反馈]
  G --> H[用户纠正]
  H --> D
```

## 三个不同的时间尺度

传输层通常一分钟封批，最大五分钟，最后提交尾段；分包服务于可靠上传，不定义现实事件。语义层可以把跨分钟的同一讨论延续，也可以在一分钟内发现不同事项。活动层将一场聚餐或周会收进一个可展开容器；主题跨活动、跨日期维护同一对象的进展。

录制时间、接收时间、上传时间、处理时间分别保存。设备时间不可靠时保留依据与精度；不能用整理完成时刻填补未知的发生时间。当前多数语义事件时间为批次或来源范围，不能承诺逐词时间精度。

## 原始事实与派生结果

`heartball_store.py` 维护会话、流、封批、重点、缺口和任务；`heartball_agent_store.py` 维护文档、引用、声明、建议、反馈与版本。`heartball_organization.py`、`heartball_topics.py`、`heartball_activities.py` 分别管理事件、跨记录主题和活动。

每份引用必须能定位当前原文或明确保留的旧版本；模型不能补写原句。多个不连续原句分别引用，不能把首尾包成一个范围而夹入别的讨论。来源纠正会使相关事件、主题、答案和建议失效，随后从保留来源重建。归并/拆分是可逆投影，不删原始输入。

## Personal Agent 的运行

`heartball_personal_agent.py` 与 `prompts/personal-agent/` 实现 observe → respond → review → publish。五分钟合并观察；没有变化不调用模型，静默观察跳过生成与复核。当前默认十五分钟冷却、滚动 24 小时最多六条反馈。独立复核检查重复、泛化建议、误归属和忽略纠正；模型之间同意不是准确性真值。

这些节点有 SQLite 检查点，失败恢复不重转写。引用和权限在发布前再校验。当前只产生空间内反馈，没有自主发消息、操作浏览器或外部执行能力。MCP 提供数据访问也不会自动唤醒 Agent，MCP 适配仍在路线图中。

## 多设备与恢复

`heartball-shared-service.py` 面向一名用户、多台设备。每设备独立凭据，可撤销；可区分只读/编辑。空间同步是持久修订号加权威快照，不是逐实体增量协议。设备之间不能接管同一采集身份。

网络补传与蓝牙漏采分开处理。前者重放相同身份、序号和哈希；后者在保存后核对原文件、结束码、大小与整文件哈希，再与已收原声做唯一字节对齐，只处理未覆盖范围。跨约三小时物理续段关联必须核查前驱、时间与哈希，歧义时不猜。

服务端没有录音控制引擎；首发抽出了独立 HTTP 传输层，移除了对未发布 Swift 探针的依赖。v0.2.0 已纳入 GPL 原生 iPhone 采集客户端，发送相应协议消息；默认 iPhone 采集、Mac 读取同一共享空间。Mac 本机采集保留为独立部署模式。

## 声音与个人归属

VAD 判断语音候选，声音标签描述环境，声纹只给相似度；三者都不独自证明这是用户本人现场经历。保留远端会议发言等有价值信息，同时避免把视频中的第一人称当成本人承诺。本人声音回放、混声和距离变化仍待验证。

SQLite 是当前权威业务账本，FTS/词法召回帮助查旧证据。没有把 Mem0、Graphiti、向量库叠成另一套事实权威。本仓库不包含可靠场景分类器或全天说话人识别承诺。
