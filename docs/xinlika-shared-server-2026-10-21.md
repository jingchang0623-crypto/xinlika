# 心力卡共享服务端 · 2026-10-21

后续状态：实体 iPhone 直连云端、真实 ASR 和两端原生纠正同步已完成本轮验证，主 Mac 已切换共享空间；蓝牙同文件实时恢复仍未通过。最新结果见 [iPhone 云端验收](xinlika-iphone-cloud-2026-10-21.md)。下文的“未切换”是初次部署时的验证边界。

共享入口为 `https://xinlika.apps.zaowuyun.com`。这是一个个人空间的多设备服务；目前不是面向公众注册的多租户产品。Mac 0.4.4 可独立连接共享空间，本机录音卡控制仍只走本机采集服务。

## 部署与复用

- 用户指定的 Ubuntu 服务器已有 `*.apps.zaowuyun.com` 泛域名 DNS 与有效证书，本服务添加独立的精确域名 Nginx 站点，复用证书路径。
- 新容器 `xinlika-shared`，AMD64，CPU 上限 1 核、内存 768 MiB；API 只绑定宿主 `127.0.0.1:18778`，经 Nginx HTTPS 访问。原有 8 个容器未变化。
- 复用现有 MobileIngest、SQLite 任务账本、voxgate（固定版本及 15 秒识别段补丁）、LangGraph 和自动事件整理逻辑，没有另造一套转写／记忆数据库。设备持续采集与 60 秒封批保持分离，最长支持 300 秒。
- ASR 桥在容器内仅监听回环地址；模型配置和密钥只读挂载，音频、正文、模型响应与任务状态进入持久卷。构建上下文由白名单脚本导出，不包含 `.build`、录音或凭据。

## 同步与纠正

每台设备有独立、可撤销的凭据，服务端只保存凭据哈希。可授予编辑或只读权限；设备采集会话绑定原上传设备，其他设备不能接管同一个采集身份。共享服务没有 BLE 或远程启停录音接口。

同步使用持久修订号与权威完整快照，并非逐实体增量协议。空间身份、日期与时区参与视图标识，换空间或跨午夜不会错误复用旧快照。Mac 断网时保留上次内容并显示连接状态，连接失败不会静默切回另一份本地数据。

纠正带版本号，旧版本写入返回 409。纠正后原文保留历史，旧事件失效，重新整理文本；不重复转写同一音频。相同上传消息丢失回执后的重试幂等，正文改变的同 ID 重放被拒绝。

## 运维入口

源码：`scripts/heartball-shared-service.py`、`scripts/heartball_shared.py`；容器与部署脚本：`deployment/shared-server/`。

服务端数据卷 `xinlika-shared-data`，应用账本位于 `/data/workspace/heartball.sqlite`，用户配置在服务器的私有目录。备份需要同时保存数据库及音频文件，不能只备份镜像。当前未配置异机自动备份。

新增设备在服务器容器内运行 `heartball-shared-service.py device add`，以 `--output` 指定私有文件；凭据不打印到终端。撤销使用 `device revoke --id`。不通过公共 HTTP 暴露设备管理功能。

部署脚本只接受不存在的新容器和新站点，拒绝覆盖既有部署；后续升级需先核对版本、空闲任务与备份，再做有明确范围的容器替换。不要在录音卡采集过程中重启手机或 Mac 的采集服务。
