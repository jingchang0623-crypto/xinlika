## 从参考中采用的设计

公开演示将助理对话与 Today、任务、记忆、能力并排展示，使用浅色渐变、圆角卡片和简洁的导航。心力球采用这种“助理陪伴 + 可查看的结果”的组织方式，用系统语义颜色支持当前系统的深浅模式。

本次修改的是独立的 macOS `HeartballLab` 原生应用。没有改动原深脑客户端、iOS 页面或服务端协议。它仍是本机验证版本，不能据此声称已实现全天候移动端后台运行或上云部署。

- **今天**：有依据的主动反馈、候选/已确认记忆入口、最近整理。无新提醒时保持安静；不编造晨报、健康数据、个人档案或日程。
- **记录**：全部记录与独立重点筛选，保留摘要、转写、原声、边界限制、文字和来源纠正。历史导入不被标成今天发生。
- **记忆**：待确认、已确认、已完成、全部。确认、纠正、完成、拒绝沿用现有版本校验和持久化接口。
- **设备**：本次状态、音频接收量、保存批次、30 分钟验证限制、下一次来源/处理选项、处理与修订记录。
- **常驻问答区**：查询已确认记忆，展示回答、版本引用和失效状态。建议问题只填入输入框，需发送才查询。当前不呈现尚未接入的外部任务执行入口。
- **常驻采集控制**：录音和重点分开。开始前展示本次声音来源、转写/模型处理的数据去向。结束重点与结束整条录音使用不同按钮；打开应用不会启动录音。

## 实现与复用

`WorkspaceView.swift` 提供工作台布局；`HeartballAgentPanel` 通过分区与筛选参数复用已有结果展示和操作；原有 `LabModel`、Swift `HeartballClient`、音频处理和 LangGraph 服务链路继续使用。没有另写一套 Agent 或复制 Today 的营销数据与品牌素材。

原生窗口重启时发现外置卷配置文件的同步 `open` 阻塞了主线程（本机采样定位到 `HeartballClient.init` 的文件读取）。将读取移出主界面执行线程，并由启动器把最小 loopback 连接描述符写入用户 Application Support 的按工作目录区分的私有目录：目录 0700、文件 0600、原子替换。音频、数据库和模型密钥仍保留在既有私有 `.build`；描述符仅包含本机地址与本机服务 token。重启后原生应用恢复连接并展示已有数据。服务重建后应通过启动器更新描述符。

## 验证

1. `swift build --product HeartballLab` 通过，打包和 ad-hoc 签名校验通过。
2. 实际原生窗口显示已归档状态、本机服务可用、16 份文档和 17 条待确认记忆对应的内容；已确认记忆仍为 0。
3. 原生 UI 实测：四页导航、已确认空状态、重点筛选（3 份重点）、原声/转写展开、两种纠正表单打开及取消、开始准备弹层显示及取消、建议问题填入及清空、空输入禁止发送。
4. `HeartballClientCheck --agent-check` 通过：读取 16 份文档、17 条候选、0 个回答，原声证据返回可解码 WAV。
5. 启动器生成的连接描述符与原 runtime 对应，权限和字段范围核对通过。

本次没有新开录音，没有发送新的模型查询，没有修改/确认已有个人事实，也没有重跑硬件连续性或 ASR 质量测试。UI 验证不替代既有采集与模型链路的实测证据。深色模式已实际查看；浅色模式采用系统颜色适配，尚未逐页视觉验收。当前没有云端外部执行器、通知推送或任意工具调用的新增交付。
