# iPhone 0.1.1：稳定性修复与后续验收

## 本轮目标

先验证一个闭环：设备录音完整进入手机 → 手机独立重试上传 → 云端返回转写完成。
本轮不做设备录音删除，不承诺锁屏后台持续同步，不把“转写完成”称为“分析完成”。

### 已实现

- 现有服务端支持的文件导入类型为 upload；不再发送被拒绝的 ios。
- 记录页显示“手机已保存”，支持不连接灵魂卡直接重试完整本地文件。
- 建会话成功后立即持久化 session ID；重试保留已部署的 v2 请求标识。
- 保存失败不推进台账；损坏台账不静默覆盖。校验下载字节、40 字节包边界、Ogg 文件哈希。
- 记录按账号、组织和服务环境隔离；旧记录归属固定到升级时的已有账号。
- Keychain 更新不再先删除旧凭证；新账号先查组织再一次保存身份。
- BLE 连接/服务发现超时绑定到当次尝试，旧计时器不能结束新尝试。
- 前台记录页每 8 秒检查处理中会话；同步期间防自动锁屏，阻止并发修改账号参数。
- Release 隐藏高级连接参数。Debug 提供指定记录的 --retry-record 启动参数，仅作用于已验证账号的可重试记录。

## 回归验证

运行：

    xcodegen generate
    xcodebuild -project Shennao.xcodeproj -scheme Shennao -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -parallel-testing-enabled NO test
    swift build
    swift run -q CoreSelfTest
    swift run -q CleanupSelfTest
    swift run -q VoiceSelfTest
    swift run -q AuditSelfTest

iOS 17 个用例：3 个协议基础、8 个上传接口契约、6 个台账/隔离/持久化用例。
HTTP 模拟验证上传类型、顺序、会话提前保存、重试标识、已验证分片跳过、失败不伪报成功；不代表生产服务或硬件验证。

Mac 141 项断言；没有归档音频时，3 组真实样本测试跳过，不能记为通过。

真机验收清单：

- 覆盖安装后旧录音和登录仍可恢复；绝不通过卸载重装“修复”。
- 已失败录音从本地重试，获得 session ID，并查询到 ready + transcript ID。
- 新录 30 秒，从 BLE 下载到 ready；连续 3 次无丢失。
- 上传中断网，恢复后重试不产生同客户端重复会话。
- 强制退出后恢复；账号切换不显示或上传其他账号的记录。
- 蓝牙关闭、拒绝权限、超时、设备正在录音时给出可操作提示。

## 已知边界

- 当前 iOS 用 XcodeGen 引用共享 Swift 源文件，不等于整个 Mac 包已支持 iOS；正式抽包另作小步重构。
- Mac、Android、iOS 的历史幂等键不同。当前仅保证 iOS 既有键的稳定性，不承诺跨客户端去重；统一键需要服务端迁移设计。
- 服务端已 failed 的会话不会被当成成功；当前客户端不自动换键创建新会话。云端失败的安全重排队应单独实现和验证。
- 本轮仅支持已验证的 CB08 固定包 Opus 路径；其他音频格式拒绝上传，避免扩展名与内容不符。
- 有 bluetooth-central 配置不代表后台同步完整可用；现阶段请在前台同步。
- 当前账号组织仍按最早 membership 选择；多组织选择器待补。
- 台账尚未加密、没有自动清理策略；本轮保留全部本地音频，不自动删除设备或手机录音。
- 开发签名真机安装与 TestFlight 分发是两件事，安装成功不等于 TestFlight 已上线。
