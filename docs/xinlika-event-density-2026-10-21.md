# 心力卡 0.4.2：按事项整理，集中记忆和聊天

参考用户提供的心力球真实截图，本版把音频上传频率、事件边界和长期主题区分开：一分钟仍是默认传输批次，不是一个事件或主题。连续几分钟讨论同一事项可以归并；一分钟内讨论不同事项仍可分别保留。今天只展示事件时间线，聊天与记忆集中到原 Agent 位置的新标签“记忆和聊天”。

## 已实现

- 新内容仍由现有模型按实际语义抽取多个事件。持续录音每新增三份有效普通转写，调度一次事项回查；录音结束且普通分析完成后补查尾段。三份是回查频率，不是强制合并范围或语义边界。
- 回查最近最多 24 个当前录音的有效普通事件，结合逐字来源判断现象、原因、补充与处理意见是否属于同一讨论；独立事项不因相邻时间被强行合并，也不把整场会议压成一条事件。
- 复用现有 LangGraph、SQLite 检查点与 OpenAI 兼容模型接口。任务可恢复、模型结构有界修复、落库幂等；写入前核对事件版本、授权、来源版本和原文引用，冲突重新生成。
- 合并保留原事件历史与全部来源文档，逐字稿、录音和独立重点不改写。新事件沿用最早来源的录制时间，不使用整理时间。一个文档中分散的引用需取覆盖原句的原文范围时，明确保存为 `span_envelope`，没有冒充精确词级对齐。
- 今天采用单列时间线。短事项显示标题与录制时间，跨片段事项或独立重点展开两行摘要，点击查看详情。移除今天的聊天侧栏和其他页面的聊天弹层；详情中的提问统一进入“记忆和聊天”。该标签内为“聊天 / 记忆 / 约定”，保留已有来源、纠正与问答能力。

升级不会自动把整个历史档案重新发给模型。本轮仅对此前已授权的三次真实会议采样显式补跑事项回查，没有新录音或新 ASR。

## 真实会议回放

使用此前用户确认来自正在进行的视频会议的三次录音。两段并非同事项的人工标签及一、三段同事项的人工标签仍只用于评估；本轮没有手工建主题关联，也没有用虚构对话替代音频转写。

| 录音 | 普通事件数（前 → 后） | 观察 |
| --- | --- | --- |
| 第一段 | 3 → 2 | 图像修改的现象与后续指令讨论归并，iPad 问题保留独立 |
| 第二段 | 1 → 1 | 单一事项保持原样 |
| 第三段 | 6 → 4 | 人物姿态相关讨论跨三个来源归并，画面色调讨论跨两个来源归并；其他事项保留 |

三项任务均一次完成；没有新增 ASR 任务。逐项核对原文档内容、录制时间和版本未变，引用均可在原文中找到，合并事件采用最早录制来源，独立重点未变。事件数量下降是实际模型整理结果，不能换算成人工准确率，也没有证明模型粒度已适用于所有密集会议。

**跨录音的长期主题关联仍有已知漏报。** 0.4.1 中第一、三段的同事项关联没有成功，本轮解决的是同一持续录音内跨传输批次的碎片化，不能据此宣称跨录音关联验收通过。原始 [0.4.1 报告](xinlika-real-loop-2026-10-21.md) 保留。
