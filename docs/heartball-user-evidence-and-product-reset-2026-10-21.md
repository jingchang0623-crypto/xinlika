# 心力卡：依据心力球真实反馈重新收敛产品

> 后续交付见 [心力卡 0.4.0](xinlika-semantic-workspace-2026-10-21.md)：事件、主题、问答与录制时间修正已接入。本文保留此前阶段证据。


核查日期：2026-10-21。全部网站操作使用 Ego Lite；未发帖、关注或修改账户。公开来源与有效截图逐项登记在 [证据清单](../research/xinlika-product-evidence-2026-10-21/manifest.json)。

## 结论

我们之前把采集实验的文件、批次、候选事实和审核状态放到了日常产品中心，方向有偏差。用户认可的体验是：随身记录无需操心，AI 自动理解发生了什么，重要内容之后找得到，已有 Agent 能用上这些上下文。低成本开源替代应围绕这些结果实现，不能靠增加面板和确认流程来接近心力球。

本轮证据支持自动事件整理、低成本主动输入和跨工具检索的价值；跨天项目关联有媒体描述，长期“成长教练”的真实效果仍缺少足够独立证据。下面分开标明，不把宣传、界面入口和已经验证的能力混在一起。

### 一个容易被忽略的反例

[停车位原图](../research/xinlika-product-evidence-2026-10-21/parking-agent.png)里，第一次询问没有找到，随后换种问法才答出 E098。截图不能分辨同步延迟、检索差异或其他原因。因此它说明链路有价值，但不足以证明“说完马上每次都能查到”。我们的验收必须包含可查时延、问法变化和更新后的正确性。

## 4. 心力卡的产品取舍

| 用户要得到的结果 | 应自动完成 | 默认界面应收起 |
|---|---|---|
| 我今天聊了什么、想到什么 | 跨批次语义分段、事件标题与摘要、重要片段关联；保留原声定位 | 分钟批次、文件名、CRC、任务重试 |
| 刚才特意记的那句能找到 | 重点优先处理，保留上下文和边界，按内容形成记忆/问答而非固定当作待办 | 单独的重点审核作业 |
| 这件事最近推进到哪了 | 同主题跨对话关联、人物与决定变化、纠正与最新状态 | 要求用户先建项目、移动文件、逐条确认 |
| AI 记得并帮得上我 | 自然语言查找，相关事件引用，少量有依据的跟进；允许简短纠正 | 每条信息都弹风险说明、无依据的人格评价 |

日常核心是“今日事件 + 主题进展 + 问 Agent”。觉察应在积累足够真实记录后生成少量有证据的反馈，不先造一个空栏目。Today 的简洁呈现与常驻对话可以参考，但不能把其全部目录、任务、能力设置都搬进首屏。

### 自动理解如何替代逐条确认

记录进入后直接可整理、可检索；不以“用户确认”作为普通处理的前置条件。AI 结合声源、说话人、上下文和时间，自动判断内容属于本人经历、他人发言、播放内容、设想还是明确承诺。优先使用最近纠正和可定位的原句。疑似内容仍可在回答中有分寸地表达，不自动变成用户画像或执行依据；只有影响当前答案的关键歧义才询问一次。

“把所有候选都设为已确认”与“把模型回答替换为长免责声明和引文清单”都不能提供这种理解。当前新增的未确认记录检索只是过渡措施，尚不等于完成这一目标。用户纠正后必须使旧总结、记忆及建议失效并更新，不能只改一处文字。

## 5. 用更少组件实现，而不是再堆框架

沿用已核对的 [Omi / OpenMuse 源码研究](personal-agent-oss-and-hardware-deep-dive-2026-10-20.md)与[实际第三方复用记录](heartball-third-party-components.md)：

- **保留 CB08 采集适配器、卡上原声和现有 Swift 客户端。** 录音卡不具备已验证的心力球相同按键语义；不能为模仿短按标记而隐藏已实测的停录风险。
- **优先复用 Omi 的对话整理、记忆证据、主动建议相关性筛选/复核思路与可独立适配部分。** 它比通用任务工作台更贴近主链路。整套部署仍有数据库、供应商服务与中文效果适配成本；目前没有声称已直接移植。
- **继续使用已接入的 LangGraph + SQLite 持久处理链。** OpenMuse 的长任务/执行回执留给真正的执行需求，不为日常记忆先上整套邮件、浏览器、审批工作台。Mem0/Graphiti 不再叠成第二、第三套权威记忆库。
- **VAD 用于减少无语音上传与识别，轻量整理处理事件，大模型按事件结束、重点、用户提问或有效新证据触发。** VAD 无法识别“这是短视频还是本人”；客户端过滤也不能节省已发生的 CB08 编码/BLE 功耗。VAD 接入与节省比例仍需测量，不能当作已实现。
- **优先打通统一可检索上下文，再开放 MCP。** 让用户现有 Agent 使用，不强迫用户天天管理心力卡。外部执行、发消息等沿用授权边界。

成本要以真实一天的有效语音时长、ASR 请求、模型 tokens、事件数、重试与存储统计后比较；开源许可不代表模型和 ASR 免费。目标是更低总使用成本，不是把云费用换成更多用户操作。

## 6. 下一轮必须通过的体验验收

1. 自然持续对话跨过分钟上传边界，今日只出现正确的语义事件；重点不会成为一份重复记忆。
2. 用户随口记一个位置/想法，无需确认即可用不同问法找回，记录“重点结束到可查”的时延。
3. 次日继续同一主题，自动关联过去决定，能回答进展和变化，不把所有录音硬合为一个项目。
4. 播放视频与现场多人交谈不被直接写成用户事实；不因不确定而要求逐条审核。
5. 一句纠正更新后续答案和提醒，旧结论不可继续引用；无有用新信息时保持安静。

现有采集、重点、ASR、结构化抽取和持久任务为实现基础；按逻辑录音归组仍是文件整理，尚未达到上面的语义事件和自动项目关联验收。本轮为证据核查与产品纠偏，未新录音、上传音频、调用 ASR，也未把 UI 草稿或合成测试冒称为完整产品交付。
