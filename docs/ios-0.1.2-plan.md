# 深脑 iPhone 下一轮规划：后台可恢复，分析可见

日期：2026-09-05。依据：当前 iOS 0.1.1、本地 Mac 源码、Android 提交 768eb3f，以及 Apple 官方文档。
本文保留修改前的诊断与规划基线，不应把所有条目视为已完成。
0.1.2 的实现范围、真机证据与未通过验收项见 [实现与验收记录](ios-0.1.2-validation.md)。

## 1. 已验证什么，下一步验证什么

用户已确认：失败录音可从手机重试上传，且云端已完成分析。
新增反馈：锁屏或切到其他 App 后，同步连接中断。

下一轮关键假设：用户无需守着同步页面，稍后回到手机就能看到录音的分析结果；
遇到系统暂停、网络中断、设备离开，也不会丢掉已下载内容或重复提交。

最小切口不是“连接永远不断”，而是“任务不会丢、能接着传、结果能看到”。
不把 CB08 持续占用当成成功：完成下载后可主动释放设备给 Mac/Android 使用。

## 2. 诊断与证据

### 2.1 锁屏中断：后台恢复链路缺失是首要问题

确定的代码事实：

- iOS/Info.plist 已声明 bluetooth-central，所以不是简单漏勾一个后台选项。
- BLEClient 使用普通 CBCentralManager 初始化，未配置状态恢复标识、未实现 willRestoreState。
- Commands.download 用局部内存数组累计数据，只有整段结束才交给上层写文件。现有 offset 重试主要针对同一次调用中的卡顿，不等于跨断连、跨进程恢复。
- iOS AppModel 没接入 BLEClient.onDisconnect，缺少连接状态事件与恢复调度。
- AppModel.sync 每下载一条就等待云端上传，然后才下载下一条；云端慢会延长设备占用时间。
- DeepBrain 使用默认 URLSession + 内存 data 请求，没有系统后台文件上传任务；请求体中的 uploadMode=background 只是服务端参数，不会自动启用 iOS 后台传输。
- isIdleTimerDisabled 只避免自动锁屏，不解决手动锁屏或切 App。

判断：以上缺口与用户反馈高度一致；没有本次中断的带时间戳 BLE/生命周期日志，
尚不能把某一次中断精确归因于系统挂起、外设超时、连接被其他客户端占用或网络暂停。
先补诊断事件，再做受控真机复现，不能直接宣称所有掉线只有一个根因。

Apple 说明：声明后台蓝牙模式不保证无限执行，需采用状态保存与恢复；后台扫描行为也不同。
后台网络传输需系统后台会话，退出进程后的上传必须来自文件。
来源：[Core Bluetooth 后台处理](https://developer.apple.com/library/archive/documentation/NetworkingInternetWeb/Conceptual/CoreBluetooth_concepts/CoreBluetoothBackgroundProcessingForIOSApps/PerformingTasksWhileYourAppIsInTheBackground.html)；
[URLSession 后台传输](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background)。

### 2.2 分析没有返回：目前缺少结果读取链路

确定的代码事实：

- 当前只读 GET /api/recordings/{sessionId} 的 status、final_transcript_id、last_error_code。
- 本地模型没有 analysis ID、分析状态、摘要、正文等字段；记录行没有结果详情导航。
- ready + transcript ID 被视为转写终点，之后不再轮询这条；它不是分析完成状态。
- 自动刷新放在 RecordsView 中，且仅在 active 时运行；启动恢复登录并不立即查询全部待处理会话。
- Android Client.meeting 已调用 GET /api/mobile/transcript/{transcriptId}。
  Meeting 模型含 title、summary、analysis.markdown/status/methods/routingReason、
  speakers、atoms、commitments、analysisAbsentReason。
- Android 区分分析 done / failed / 处理中；iOS 应沿用真实契约，不能另造 completed 枚举。

13:37 左右只读取得的手机台账：3 条都有 session ID；1 条 ready 且有 transcript ID；
2 条本地仍为 processing。这里只能证明手机保存的状态，不能据此推断那两条云端仍在处理。
用户反馈的分析已完成与“手机尚未取回”可以同时成立。

## 3. Mac / Android 借鉴清单

| 能力 | 已看到的参考实现 | iOS 取舍 |
| --- | --- | --- |
| 设备连接 | Mac Monitor 的意外断连回调、按设备冷却、空转退避、同步后释放 | 复用决策；后台改成事件驱动，不照搬桌面常驻轮询 |
| 下载恢复 | Android Importer 的 offset/resume 与服务持有任务；Swift 现有同调用 offset 重试 | 提升为持久化检查点；不宣称 Android 内存缓冲可跨杀进程恢复 |
| 云端上传 | Android FileVault + UploadWorker，联网约束、唯一任务、指数退避 | 相同业务语义，iOS 用文件型后台 URLSession，不移植 Android Service/WorkManager |
| 结果详情 | Android MeetingScreen 的摘要、分析正文、判断和承诺 | 原生展示核心阅读内容，优先复用现有 mobile API |
| 完整转写/说话人 | Mac 在深脑打开、说话人辅助；Android 一次性 web-ticket + 内嵌网页 | 第二入口复用网页，减少早期重复实现播放器和逐字编辑 |
| 跨端历史 | Android /api/mobile/sessions 与离线缓存 | 手机本地任务和云端历史合并展示；session/transcript ID 对账 |
| 账号设备安全 | Mac DeviceBinding 的账号错配拦截 | 补设备归属提示与确认，不能只隔离“已经下载的台账” |
| 诊断与安全清理 | Mac 台账审计、完整性和删除护栏 | 先做导出诊断与空间提示；设备自动删除延后 |

以上是源码对照，不是对另外两端的真机质量背书。
尤其不要机械复制 Mac 的常驻扫描、短录音阈值，或 Android 的生命周期实现。

## 4. 下一版 0.1.2：两条工作线，一个验收目标

### A. 后台安全与恢复（P0）

1. 先建可观测状态机：发现、连接、下载、暂停、等待设备、重连、完成、需人工处理。
   日志记录版本、任务标识、App 前后台事件、蓝牙错误域/码、已落盘字节、重试次数；
   不记录 token、密码、录音正文或签名上传 URL。
2. 下载与上传拆成两个队列。BLE 串行下载，完整文件入本地队列后即可处理下一条。
   云端首版限制一个任务，避免内存峰值和令牌刷新竞争。
3. 下载写临时文件 + 持久化检查点（设备、本地账号范围、候选文件名、预期大小、偏移、校验信息）。
   只有可靠落盘字节可作为恢复点；恢复前核对设备文件未变化。
   固定包边界、设备 offset 语义和重叠数据处理必须用 CB08 实测，不盲目拼接。
4. BLE 接入恢复标识、恢复回调、断连事件；退避重连，用户取消优先。
   恢复后重建 delegate、特征与订阅，不沿用旧对象的“已经就绪”假象。
5. 独立的 iOS 文件型后台上传器；持久化 taskIdentifier、session ID、分片序号与步骤。
   PUT 后的 complete → stop → finalize 也要可恢复，不能只保证上传了二进制。
   处理上传地址过期重新取票、401 单次刷新、可重试与永久错误分类。
6. 返回前台立即对账：系统上传任务、本地任务、服务端状态三者协调，
   不依赖用户进入“记录”页面或手动点刷新。

保底行为：后台暂时不能执行时显示“已保存，等待恢复”，不伪报失败/完成；
正常下载完成后显示“已同步，设备待机”，不把主动释放连接称为异常断开。

### B. 分析结果可见（P0，与 A 共享任务状态基础）

1. 增加记录详情页：标题、摘要、分析正文、关键判断、行动项/负责人、参与者。
   缺失字段有明确说明，正文支持 Markdown 和动态字体。
2. 数据层区分三条状态，不塞进一个 ready：
   本地采集/上传状态、云端转写状态、云端分析状态。
   页面可显示“上传完成 → 转写中 → 分析中 → 分析完成”，
   分析不存在、失败、未刷新分别呈现。
3. 接入 Android 现有 mobile transcript API；
   实现前核对生产响应与权限、空值、状态枚举、schema 测试样例。
4. App 回前台与打开详情立即刷新；前台处理中采用有上限的退避轮询，
   已完成结果用缓存并支持手动刷新，不反复刷新全部记录或反复刷新登录 token。
5. 离线展示上次成功结果并标明更新时间；网络失败不清空已缓存正文。
6. “查看完整转写/回听”提供带一次性票据的同源网页入口。
   token 不放 URL，登出/换账号清理隔离网页会话，外链交系统浏览器。
7. 人工“开始分析/重试分析”单独按钮、明确可能消耗额度，使用服务端幂等约束；
   不能因为轮询失败就自动重复启动分析。

### 交付顺序

先交付诊断事件、状态拆分和详情读取的小包，快速确认数据契约；
接着交付下载检查点、后台上传与蓝牙恢复的小包；
同一轮真机验收通过后再标记 0.1.2 稳定。不要把“结果页能打开”当作后台问题已解决。

## 5. 后续版本

### 0.1.3：日常使用与跨端一致性

- 云端历史列表、分页/搜索、本地待同步记录合并；在 Mac/Android 上传的内容也能在 iPhone 看见。
- 设备记忆、账号归属提示、上次同步时间、电量/空间、单条进度与整体进度。
- 完成通知、网络策略（Wi-Fi 优先/允许蜂窝），明确通知权限与联网成本。
- 分析分享必须由用户触发，不自动生成公开链接。
- 脱敏诊断导出、本地空间统计、缓存保留策略；删除须保留可恢复路径并确认云端完整副本。

### 0.2：扩展价值

参考 Android 的“今日判断、承诺待办、搜索、问深脑”，先以实际使用频次挑一个入口验证。
iPhone 麦克风录音、实时转写、原生逐字播放与说话人编辑列为候选，不阻塞当前硬件闭环。
自动删除灵魂卡录音、全量后台常驻、全端 UI 统一、客户端重写分析引擎不进入这轮。

## 6. 高效维护的边界

- Apple 共享：协议/帧解析、音频封装、台账和状态迁移、API DTO、错误分类、幂等规则。
- 平台独立：iOS 后台生命周期/文件上传、Mac 常驻监控/桌面文件访问、各自 UI。
- Android 继续 Kotlin 原生；与 Swift 共享的是 API schema、状态定义、错误码、音频黄金样例和验收场景，不是强行共享 UI 代码。
- 服务端是分析业务规则的唯一来源；分析阈值、完成枚举、能力支持不在三个端复制三份。
- 当前先沿用 XcodeGen 引用共享源码，稳定后再抽可独立测试的 Apple Core 包，避免边修后台边大规模迁移。
- 每次共享核心变更必须跑 Mac build/self-tests + iOS tests；Android 对相同契约 fixture 回归。
  SDK/系统升级和关键 BLE 改动再跑真机矩阵。
- 历史幂等键跨端不同：统一需要兼容迁移，不直接把 iOS 键替换成 Android/Mac 键。

## 7. 出口标准（目标，不是已通过）

| 场景 | 通过条件 |
| --- | --- |
| 用户现有 3 条录音 | 本地/云端对账正确，已完成分析可在手机查看；不重新创建重复会话 |
| BLE 下载中切 App / 锁屏 | 在设备支持的情况下继续；若暂停，可靠保存并恢复，不悄悄从零开始 |
| 返回前台 | 立即触发对账；正常网络下 10 秒内展示最新状态或明确网络错误 |
| 网络断开 → 恢复 | 本地录音不丢，自动或一键接续；同客户端只有一个会话 |
| 系统终止 / 用户强制退出 | 分开验证；用户强退后不承诺系统自动重启，重新打开可找回任务 |
| 新录音 30 秒、10 分钟、1 小时 | 每类至少 3 轮，字节完整、可解码、时长合理、结果可达 |
| 弱信号 / 蓝牙关闭 / 外设休眠 | 状态和原因可见，重试有上限，不无限转圈、不误报成功 |
| 账号切换 / 存储不足 | 无错账号上传、无跨账号缓存显示、写入失败不覆盖已有录音 |
| 正常同步收尾 | 主动释放设备不显示为异常；云端结果刷新不受 BLE 断开影响 |

最终要交付的不是一个“永不掉线”的动画，而是一条用户可以信任、可恢复的录音到结果流程。
