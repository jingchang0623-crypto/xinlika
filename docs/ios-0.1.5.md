# iOS 0.1.5 (6) · 导入保护与结果优先

## 问题与决策

用户反馈误触产生一批约 3 小时的录音，旧版会持续下载、上传并触发深脑处理。旧版仅将自动连接做得更顺畅，没有在进入队列前判断是否需要用户确认，而且下载暂停与上传暂停分离。新版将“可自动连接”与“允许处理某条录音”分开。

默认以下录音进入「待确认」，不启动新的音频下载或云端提交：

- 时长不足 1 分钟；可在设置改为 30 秒、2 分钟或关闭此项。
- 时长达到 2 小时；覆盖此次约 3 小时的误触录音。
- 一次完整设备列表发现 5 条及以上新录音。按唯一文件身份去重，并排除当前正在录制的文件。
- 时长未知、设备列表不完整。
- 升级前尚未完成的本地队列，包括部分下载、已下载、上传中及失败项目。

阈值是可调整的产品假设，不代表短录音或长录音必然无效。普通时长、少量的新录音仍可自动处理；不分析音频内容，也不会自动删除硬件、手机或云端的文件。

## 用户操作

记录页右上角「待确认」进入录音管理。默认不勾选任何录音，可多选或全选后忽略，也可选择「导入并分析」；后者显示条数、总时长与分析额度确认。

忽略立即持久化，后续设备扫描、应用重启和自动重试都不会重新纳入队列。已忽略项目可恢复；尚未完成的项目恢复到待确认，再次确认后才能处理。正常结果也可通过记录的上下文菜单隐藏到已忽略列表。

设备页或记录页「更多」中的「暂停同步」统一暂停 BLE 下载、本地上传调度及系统后台 PUT。暂停状态跨重启保留。「检查录音」在暂停状态下只检查列表，不恢复音频传输；确认录音也不会擅自解除全局暂停。

已发给服务端的处理请求或已开始的云端分析，不能保证被本地取消。当前未验证到云端取消 API，因此不承诺撤回已提交分析或退还已扣额度。

## 实现约束

- 全批次审核状态在开始下载前原子写入 ledger；写入失败停止处理，不以默认允许掩盖错误。
- 队列每个项目与每个云端提交步骤都重新读取最新暂停和审核状态。认证失败后的内部重试也重新检查。
- 创建会话返回后先保存会话 ID，避免取消时丢失已有云端身份。沿用既有幂等键，不为恢复任务另建分析会话。
- 后台传输取消会释放等待者，并隔离旧传输迟到的回调，避免快速恢复后误伤新任务。
- 录音审查、忽略身份和设置按账号、服务环境与组织隔离。系统后台旧任务在升级迁移及账号恢复时取消。
- 如实际音频长度与设备报出的时长不符，下载完成后还会复核短/长时长；已经明确批准的录音不重复询问。

## 界面

记录页直接呈现标题、摘要和分析状态；取消常驻的大块同步说明、重复的云端更新成功提示。仅在传输或暂停时显示一行状态，待确认入口位于工具栏。

设备页改为原生 Form，保留连接、同步和录音管理；固件、信号、文件数和最近检查时间折叠到详情。设置移除说明性段落，保留导入保护选项。阅读页移除常驻的泛化提醒，错误、额度确认和必要操作提示按需呈现。

依据 Apple 官方 [Writing](https://developer.apple.com/design/human-interface-guidelines/writing) 与 [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：重要内容优先、文字简短、使用动词命名操作、次要信息按需展开。通过 Ego Lite 阅读，采用 SwiftUI 原生 List / Form / Menu / 多选 / 确认面板。
