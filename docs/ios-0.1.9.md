# 0.1.9 (10)：保存后找得到短录音

用户确认 0.1.8 的开始、结束录音已可用，但找不到十几秒的测试文件。本次实机只读检查在 CB08 / V1.0.0 上找到 `note20260907-131300.`，时长 22 秒、44,600 字节。文件列表完整，共 16 条；没有在这次检查中新建、删除录音或下载音频。列表元数据证明文件仍在卡上，不代表已验证音频内容。

## 原因

13:13 的操作日志显示开始和保存均由设备状态确认；保存后 13:13:39 发起的同步在 13:13:41 被取消。旧版 `controlRecording(nil)` 即使只是刷新状态，也会取消正在连接或读取文件列表的同步。此前读取的手机账本只有 11 条旧记录，没有这条 22 秒文件。

手机的短录音门槛为 120 秒。短录音需要确认后才传输，但旧版把文件发现与传输绑定，暂停同步时保存后不会登记文件；待确认队列又把长录音排在前面。因此“保存成功”并不总能立即找到对应文件。

## 修改

- 只读状态刷新不再取消正在进行的设备同步。
- 保存确认后独立读取卡上文件列表、登记元数据，即使同步暂停也能发现新文件；保留原导入门槛、忽略决定和上传开关。
- 保存后提供“查看录音”，短录音直接打开待确认队列并定位该文件，其他录音打开详情。弹层由稳定的页面容器持有，避免 Form 行状态更新导致弹层消失。
- 打开录音管理会尝试更新文件列表；已有设备同步时复用它的结果。队列按录音时间从新到旧排序。
- Debug 增加显式指定设备的只读目录诊断入口；Release 排除该入口及模拟开关。

读取目录不会批准文件，也不调用音频下载或云端分析。异常断连时保留已确认的结束状态，简短提示文件列表待更新。短录音不是无效录音，依然允许用户手动确认“导入并分析”。
