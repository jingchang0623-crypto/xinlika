# 从关注到真实使用

本轮只准备仓库与传播素材；以下为建议节奏，没有预约代发或外联。

| 顺序 | 内容 | 给读者的一个动作 | 看什么反馈 |
|---|---|---|---|
| 首发 | iPhone + 硬件不到 200 元的开源路线，附原生截图及合成标注 | clone 并跑演示 | 安装成功/失败、进入哪个完整运行路径 |
| 第二篇 | 原句纠正如何改变后续回答，展示前后报告 | 用合成样本复现纠正 | 是否看懂出处与旧答案失效 |
| 第三篇 | 录音卡断连、本地保存与补传的工程边界 | 复现一个协议失败测试 | 有输入/环境的 Issue 或修复 |
| 第四篇 | Android 跨品牌扩展，先从文字工作台开始 | Fork 并说明第一份交付 | 有具体目标、后续提交的 Fork |
| 后续 | 汇总第一次运行的真实阻碍，发布修复 | 再跑曾失败的步骤 | 同一问题是否被解决 |

使用 [copy](copy.md) 中的相应段落，不在所有渠道机械重复相同文字。发布前复查对方社区现行规则、兼容来源日期与项目状态；不去竞品评论区刷链接。

基线与第 7/14 天用同一口径记录：仓库访客/clone、第一次运行反馈、可复现问题、贡献 PR、有实际改动的 Fork。Star/Fork 总量不是成功运行、留存或模型效果。GitHub 流量有统计窗口；注明窗口和采样时间，不用一次帖子差值作因果证明。

没有真实数据时留空，不填预期增长作为业绩。不加入隐藏遥测；体验反馈由使用者主动选择。页面兴趣高但跑不通时，优先修文档和配置路径；Fork 多但无改动时，缩小第一份交付并清楚回应验收问题。
