# 深脑 iPhone：原生阅读体验方案

版本：设计预览 v1 · 2026-09-05。先确认体验，再分批替换生产 UI。

后续进展：用户已确认方案，正式 target 的首批落地见 [iOS 0.1.3 实施与验证](<<LOCAL_HOME>/Documents/ChatGPT/深脑 app/docs/ios-0.1.3.md>)。下文保留原始设计阶段的范围与判断。

已完成可运行的 SwiftUI 设计预览：[查看五屏实际截图](<<LOCAL_HOME>/Documents/ChatGPT/深脑 app/docs/design/preview-gallery.md>)；[验证记录](<<LOCAL_HOME>/Documents/ChatGPT/深脑 app/docs/design/validation.md>)。

## 1. 真正要解决的问题

不是“给所有文字加一个圆角”。用户回到深脑，要完成三件事：找到一段录音、迅速理解它的价值、深入阅读并核对原话。现有页面把标题、状态、调试信息和长篇正文做成同等权重的设置行，导致内容没有主次。

现有真实报告达到约 8,521 和 21,392 字符，并包含大量标题、列表及表格行；短文本样例无法代表实际阅读体验。旧 `MarkdownBody` 按空行切段、主要使用行内 Markdown，不能承担正式的长文排版。

设计验收的目标：用户不必理解 BLE、上传阶段或分析路由，也能知道“内容在哪、是否可读、遇到问题怎么办”。不以增加 AI 调用或重新上传旧录音换取外观改善。

## 3. 三档方案

以下为范围估算，不是交付承诺；真机、账号和跨端状态验证会影响时间。

| 方案 | 核心思路及优势 | 风险和开发投入 | 时间估算 / 适用条件 | 不选择的代价 |
|---|---|---|---|---|
| A 安全渐进：原生简报与阅读器（推荐） | 保留数据链路；换信息层级和展示层；快速改善高频路径 | 中等投入；需要真实 Markdown 渲染与旧状态回归 | 约 3–5 个开发日，另留真机验证窗口；适合当前 P0 刚完成阶段 | 放弃最快获得可读性提升、最小业务回归面的路径 |
| B 激进重构：跨录音知识流 | 首页直接展示跨会议主题、决策与行动；结果更可行动 | 高投入；新增归并模型、跨端编辑和同步冲突处理；容易模糊原始出处 | 约 2–4 周起；需先验证跨录音需求与服务端能力 | 暂缓知识库式体验，但不会阻碍原始记录阅读 |
| C 理想预算：多端知识工作台 | iPhone 捕获与回顾、Mac 深阅读与编辑、跨端链接/检索/离线全文 | 很高投入；需要专门设计、数据模型和多端测试体系 | 约 2–3 个月起；需稳定团队及明确预算 | 暂缓完整工作台，避免当前阶段过早扩展产品范围 |

选 A，不重构已经验证过的同步和分析流程。卡片是信息分组工具，不是所有内容的统一容器。

## 4. 页面设计

### 记录：默认首页

- 底部稳定保留“记录 / 设备 / 设置”三个入口，各自保存导航历史。
- 采用原生 `List`，按日期分组。每条记录包含可读标题、时间和时长、两行内容摘要、一个最重要的状态。
- 点击整行进入详情；不再分成“记录操作”和“查看分析”两个容易误点的入口。
- 原生搜索按标题、摘要筛选。生产版本后续加入全文索引，不把预览的内存筛选冒充全文检索。
- 隐藏字节数、服务器会话 ID、固件和路由解释；必要时放“详情/诊断”。异常仍显示“上传失败 / 待恢复”等具体状态。

### 概览：一段摘要 + 少量重点卡片

- 内容标题和录音元信息在前；“概览 / 完整分析”使用系统分段选择器。
- 摘要使用轻微蓝色底，呈现已有摘要，不再调用模型生成新摘要。
- “关键判断”按独立观点分卡；每卡只讲一个判断，可展开核对已有原文引用。
- “行动建议”使用紧凑列表，不放假的勾选框：目前缺少跨端完成状态，就不暗示已实现任务系统。
- 没有判断/行动字段就不显示相应区域；没有摘要时明确说明并提供完整分析入口，不擅自从截断正文造出“摘要”。

### 完整分析：连续阅读器

- 白色/深色语义背景上的连续文档，不给每个段落套卡片。
- 标题、二三级标题、段落、引用、列表、表格分别排版；正文支持选择复制。
- 长文提供目录弹层和章节跳转。未来按会话 ID 保存阅读位置。
- 窄屏表格只在表格内部横向滚动，保留完整单元格；文字极大时考虑字段列表替代。
- 工具栏保留“转写与回听”，没有真实音频与锚点就不展示虚假的播放进度或时间跳转。
- 本轮预览使用结构化示例块展示目标样式，**不是已完成的通用 Markdown 渲染器**。

### 设备：只回答能否同步、同步到哪

- 设备身份、连接状态、电量和最近同步时间。
- 当前任务显示可解释的进度与恢复提示；正常同步收尾和异常掉线用不同文案。
- 技术信息折叠在次级入口。不以“始终连接”替代系统后台约束下的真实状态。

### 设置：采用原生 Form

- 正式版包括账号、分析额度、阅读外观和诊断入口；退出账号等破坏性操作分组、确认。
- 预览只实现外观切换与范围说明，没有可操作的真实账号/网络/设备设置。

## 5. 视觉与 Apple 规范的关系

- 系统字体与 Dynamic Type；正文 `.body`，主标题 `.title`，小节 `.title2/.title3`，辅助信息 `.subheadline/.footnote`。不把超小字号当精致。
- 语义颜色：主/次文字、系统背景、分组背景；蓝色只用于重点和可操作元素，状态同时有图标与文字。
- 本项目约定：页面边距 20pt，卡片内边距 16–20pt，圆角 16pt；章节间距 24–32pt，段落间距 12–16pt。**这些是项目设计决策，不是 Apple 强制数值。**
- 项目可点控件目标至少 44×44pt；大字号不裁切正文，不限制辅助功能字号上限。
- 系统导航与控件随 iOS 呈现平台材质；不自行给正文卡片添加 Liquid Glass。iOS 17 保留原生兼容外观，iOS 18+ 使用新 Tab API。
- 不为卡片增加装饰阴影、渐变背景或无意义图标。

依据：[布局](https://developer.apple.com/design/human-interface-guidelines/layout)、[字体](https://developer.apple.com/design/human-interface-guidelines/typography)、[集合](https://developer.apple.com/design/human-interface-guidelines/collections)、[标签栏](https://developer.apple.com/design/human-interface-guidelines/tab-bars)、[材质](https://developer.apple.com/design/human-interface-guidelines/materials)、[可访问性](https://developer.apple.com/design/human-interface-guidelines/accessibility)。文字内容适合列表；Liquid Glass 用于控制和导航层，不用于内容层。可参考 Notes 的层级内容组织、Safari 阅读器的连续阅读，而不是复制某个系统 App 的皮肤。

## 6. 从方案到生产的推进顺序

1. **本轮：隔离的 SwiftUI 设计预览。** 展示记录、概览、长文及设备/设置方向；示例数据，与真实服务无连接；只安装模拟器，不覆盖手机工作版本。
2. **阅读链路第一批。** 提取语义样式与只读展示模型；替换记录列表和概览；保留现有 AppModel、Ledger、上传/结果回收逻辑。没有后端字段就降级显示，不假造状态。
3. **长文第二批。** Markdown 解析成块（标题、段落、列表、引用、表格），解析与 UI 更新隔离，使用稳定块 ID。目录、复制、阅读位置随后落地；用真实报告结构验收，而不只用短样例。
4. **设备/设置第三批。** 展示真实同步阶段与失败恢复入口，保留诊断能力但降低视觉权重。
5. **真机灰度。** 单独构建安装，原始录音不删除、不重复上传、不触发额外分析；视觉验收之外继续补做断连恢复及后台上传测试。

### 验收矩阵

| 维度 | 必须覆盖 |
|---|---|
| 文字 | 短摘要、2 万字符报告、多级标题、超长标题、列表、表格、多字节中文 |
| 状态 | 空列表、搜索无结果、分析中、失败、离线缓存、部分结果、无自动分析原因 |
| 视觉 | 浅色、深色、大字号、最小支持屏宽、横竖屏/安全区；长文不横向溢出 |
| 交互 | 整行进入、返回位置、分段切换、目录跳转、引用展开、转写入口 |
| 可访问性 | VoiceOver 顺序、标题导航、按钮命名、非颜色状态、至少 44pt 操作目标 |
| 回归 | 既有 34 项 iOS 测试、Mac 断言集；真实录音与服务器 session 不变；锁屏与切 App |
