# 心力卡 Harness² 隔离接入与实录优化

本轮已接入 Google Research 的 Harness² 官方递归、证据构造、候选组合与经验库，完成一次小规模自动优化，并将候选冻结后送入独立留出集。运行与结果详见下文；没有自动启用到采集或共享服务。

## 实际接入

固定上游提交 `1cfe254e8d25b15f37048c3730134686abe60335`，Apache-2.0。直接调用 `core.schedule.run_domain`，使用 `k=1`、顺序模式，执行基线 → 通用改进／领域改进 → 组合 → 经验提取。使用 OpenCode 的配置树协议，但没有启动 OpenCode 或 Codex 执行器：心力卡提供自己的冻结实录领域执行器，以及只能编辑三个 Skill 文件的模型通道。不能把这次实验称为原生 OpenCode Agent 的效果对比。

- `heartball_skill_bundle.py` 校验清单、相对路径和 SHA-256，并在加载时冻结内容快照。
- 增量、滚动整理、独立复核三个提示词分别放进 Skill；实际模型调用读取候选内容，回执记录对应内容哈希。
- `heartball_harness2.py` 实现官方任务适配接口。每个候选独占 SQLite、任务、缓存、结果和轨迹，只消费已有转写。
- `optimize-xinlika-harness2.py` 组织实验与冻结，`evaluate-xinlika-harness2.py` 在优化完成后单独读取检查标签。
- 可编辑面仅三个 Skill；录制时间、来源分配、权限、纠正、事务、评测器、标签和执行代码不交给优化器修改。
- 外层模型计量器记录实际请求；相同源材料、配置树和执行条件的回放复用结果，子计量器用于归因，不重复相加。

默认清单是 `prompts/bundles/xinlika-events-v1.json`，保持历史提示词行为。另有显式选择的 `prompts/versions/xinlika-events-v2/bundle.json`：仅将按位置计数的来源分配改成显式片段编号，并由宿主绑定已观察到的主题版本。这是协议修复，不能记为 Harness² 的语义收益。严格 JSON Schema 是请求约束，服务端仍出现过不符合结构的回答，因此宿主校验与有界修复不可省略。

## 执行结果

第一轮旧数组协议未完成整轮回放：续写句柄、分配项数量和主题版本均出现校验失败。没有交付物，未执行留出集；27 次实际请求、342,251 tokens，全部保留在成本账本中。

第二轮在相同的显式编号协议下对比基线和自动候选。基线未完成开发回放；自动候选完成 17 个增量窗口及滚动整理，612 个原始片段均有且仅有一次分配，原文未变。最终首页 47 件事件；这个数量本身不是质量指标。

自动修改只发生在增量 Skill：加入“片段 → 事项、事项 → 原始片段”的双向提交检查，避免无来源事项和无归属片段。滚动及复核 Skill 保持不变；没有写入用户人物、事项或检查答案。

冻结候选哈希：`7d522f5fa54907180785b231f53fa9dbf9f84b6f3192b2a9dc3227ec1b9c0ac4`。

开发集九项检查中，5 项通过、2 项失败、2 项因所选场景无对应来源未评分。失败是：把画面风格和 iPad 图片引用问题误合并；遗漏已知画面创作跨对话关联。因此即使独立检查全部通过，也不能声称当前候选已满足全部目标或可直接替换运行版本。

## 启用、复现和限制

可通过模型配置中的 `skill_bundle` 显式指定候选清单；采用 v2 协议时同时设置 `structured_incremental: true`。当前真实运行配置没有切换。候选只在 `.build` 下，不会被服务端发布包顺带启用。

可选研究依赖放在 `requirements-harness2.txt`，固定官方 Git 提交，要求 Python 3.12 或 3.13；不加入录音服务的常规启动依赖。本轮用隔离 Python 3.12 环境及固定本地官方源码执行。

准备命令接受私有 `--split-plan`、开发 `--cases` 和 `--holdout-cases`，按录制组和明确时间范围导出，同时冻结标签与评分函数；`prepare` 必须使用新 `.build` 目录。随后运行 `optimize`，结束后用 `evaluate-xinlika-harness2.py --public-output ...` 生成脱敏结果。真实转写、模型输入输出、凭据、标签和实验库仅留 `.build`。

实测结束后另外补齐了运行保护：完成的实验只读复用；已存在模型账本或运行占位的中断实验拒绝重置，需用新目录。缓存身份覆盖完整领域执行源码及结构协议配置，适配器运行中源码变化会拒绝执行；同适配器串行执行避免相同候选并发重复付费。失败轨迹增加真实被拒回答与输入，准备步骤自动登记评测哈希。这些是本轮结束后的工程加固，没有再调语义提示词或调用模型，不能将其描述为刚才实验已使用的优化条件。

验证：218 项相关测试通过，包含候选实际进入模型请求、版本／路径边界、冻结来源、真主题并发版本、明确片段编号、外部门槛、失败轨迹、评测登记、重复运行保护与缓存失效。已完成实验再次执行 `optimize` 在无模型配置、无上游路径时返回已有结果，新增模型调用为零。服务端源码导出检查通过；实验优化 CLI 与研究依赖仍作为独立工具使用，不冒充已部署优化服务。

这里是离线 Skill 改进，不替代共享服务的权威业务账本。Harness² 经验库保存通用处理经验，不是用户个人记忆。官方 `k=1` 选择会采用唯一组合候选，必须另设基线回退和质量门槛；上游“选中”不等于独立验收通过。

本轮没有音频上传、ASR 请求、硬件命令、生产写入、服务重启、Git 提交或外部发布。采集、现有转写和线上整理按原配置继续运行。
