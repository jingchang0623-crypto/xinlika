## 已经可以使用的行为

独立的 `HeartballLab` 原生 App 提供“开启／结束持续记录”和“开始／结束重点”两组操作。持续记录开启后，重点记录引用同一条音频流的范围；结束重点只封好当前批次、保存独立记录并建立处理任务，不向硬件发送停止或重启命令。3 秒短片段也保留，不受环境录音的 60 秒筛选阈值影响。

后台服务独占一个探针子进程，采用正常厂商前台握手；原生界面通过独立的 Heartball API 访问它，不建立第二个 BLE 连接，也不冒充现有 DeepBrain 六步协议。全局结束才保存本次身份明确的设备文件，随后在空闲状态完整下载它进行归档核对。物理保存键仍按全局停止处理，不自动重新录音。

默认每 60 秒封批，服务接口允许设置 60–300 秒。重点结束或全局结束会提前封好尾段；这是软件范围处理，不是每分钟停启录音笔。批次保留会话、连接、序号、原始字节范围、哈希、接收时间和缺口。当前 40 字节／20ms 换算依赖本台设备已验证的编码基线，不能自动推广到其他编码配置。

SQLite 事务保存会话、音频批次、重点、任务及事件；原始批次写入私有文件并核对哈希。相同音频复用识别任务，重点分析引用所覆盖的批次，避免同一段内容重复识别。现阶段任务均停在质量审核状态，不调用 ASR、不上传音频、不写个人记忆。归档补回的极短尾音进入需要上下文合并的审核任务，不单独发送一个亚秒片段去识别。

## 启动与停止

在项目根目录运行，需要 macOS 14+、Xcode Swift 工具链和 Python 3：

```bash
python3 scripts/run-heartball-lab.py --device YOUR_DEVICE_UUID
```

启动器构建探针和原生客户端、启动仅绑定 `127.0.0.1:18766` 的服务，并打开 `.build/HeartballLab.app`。设备 UUID 由调用者传入；默认运行状态位于 `.build/heartball-lab`，凭据保存在其中的私有 `runtime.json`，不应复制到文档或提交 Git。再次启动可复用已保存的设备配置。

打开 App 不会自动录音。先让手机上的录音 App 断开，再在界面明确开启持续记录；测试结束使用“结束持续记录”，等待保存和归档完成。关闭 App 窗口不等于停止后台采集。当前实验入口默认最长采集 **30 分钟**，界面展示此限制；它不是全天候产品设置或续航承诺。服务自身可通过 `--max-seconds` 设置受限实验时长，启动器采用默认值。

所有音频、正文和凭据留在被 Git 忽略的 `.build`。服务不是公网部署，手机上的 `127.0.0.1` 也不能连接这台 Mac。现有深脑客户端与上传路由未切换；旧 `cb08` heartbeat 保持暂停。

本次从原生界面开启一份专用持续录音，在同一流中完成三段重点，再从界面结束全局采集。第二段使用相同 Swift API 客户端进行幂等重试验证，其余重点使用原生按钮。证据与运行时源码哈希见 [脱敏结果](validation/heartball-local-2026-10-21/results.json)。

| 实时收到 | 421,920 字节，编码基线 210.96 秒 |

| 重点操作中的硬件命令 | 0；没有停止、继续或重启 |
| 全局硬件操作 | 开始 1 次，最后保存 1 次；无断连、无物理文件变化 |
| 落盘 | 采集队列丢弃 0，写入失败 0，严格解码通过 |
| 服务重启 | 完成态会话、三条重点、六个批次和十个待审核任务的身份及内容保持一致；Swift 客户端重新读取成功 |
| 外部处理 | ASR 调用、外部音频上传、个人记忆写入、卡上删除均为 0 |

这里的“无内部字节缺口”仅表示已收到的完整编码流相对于这份卡上参考文件逐字节一致，不等同于麦克风采样连续、按下瞬间无延迟或逐字不漏。末尾差异被明确保留，没有用短到达间隔或“录音中”状态替代完整比对。

重点边界当前基于用户请求时已经接收、落盘的音频包位置。设备编码、BLE 和主机处理存在延迟；尚未校准意图时刻到 ADC 采样的位置，也未验收前后缓冲、词级边界或重叠语音。界面中的独立记录目前是可寻址的音频范围和待处理状态，不能称为已完成的内容整理或 Agent 反馈。

## 硬件握手与产品交互结论

正常前台、后台协议握手的各一次人工按键试次均无断连，实时接到卡上文件的起始编码；前台试次全量与卡上一致，后台末尾缺 40ms。后台只是 Mac 发送厂商状态通知，不是 iOS 后台生命周期验收。完整过程见 [按键与双场景实测](cb08-dual-mode-recording-2026-10-21.md)。

亮屏短按产生真实保存请求后，正常回应、失败值 2、实验零值、不回应和挂起时单发继续命令，已测路径都最终停止并保存。黑屏首按仅唤醒，不能当作重点事件。普通→电话→普通拨动时，用户观察到计时继续；同一专用文件保存 334.04 秒，无断连，但未识别出可可靠消费的独立拨动事件，也未验收声音通道变化。因此当前持续模式的非破坏重点入口使用 App；不能宣称机身保存键已变成重点键，或电话模式可替代重点模式。
