# 心力卡：全天声音标签与本人声纹

当前共享服务 r10 已接入独立声音模型进程，iPhone 0.3.5(19) 增加三段声纹登记。新封存且已授权整理的批次自动进入持久队列；不默认回扫历史录音。实际使用仍保留“声纹相近不等于本人现场说话”的边界。

## 复用与链路

模型复用 [sherpa-onnx 官方 API](https://github.com/k2-fsa/sherpa-onnx/tree/a63f82130d91d99a23a43f346104706881b31ff1/python-api-examples)：Silero VAD 提供语音区间，Zipformer-small int8 提供每十秒声音标签，中文 WeSpeaker 提供粗粒度五秒说话人向量。代码负责批次身份、授权、队列与业务证据，没有自行训练或重写神经网络。标签和声纹阈值尚未经过通勤、距离及回放场景的充分校准。

设备持续接收、60 秒封批（最长 300 秒）与模型推理解耦。声音 worker 只读已封存原声，校验原始哈希、严格解码；按模型版本与音频哈希去重，持久租约可在重启后恢复，错误有有限重试。声音证据与现有逐字稿共同进入自动事件、长活动及 Personal Agent 分析；不重复调用 ASR。登记录音关闭 ASR 和事件整理，只用于用户明确发起的声纹登记。

云端 worker 与主 API 分容器：0.5 CPU、768 MiB 上限、运行时无网络，模型目录只读，无服务密钥或录音卡控制。观察到处理两个 60 秒登记批次分别约 7.91、7.65 秒；运行时占用约 311 MiB，非全天峰值或稳定性承诺。可复现部署文件见 `deployment/shared-server/ACOUSTICS.md`。

## 声纹与内容归属

登记要求安静环境、用户确认独自说话及三份独立录音。前两份构造参考，第三份只做独立一致性复核；有效语音不足、严重削波或向量不一致会拒绝，不降低门槛凑成功。本轮三段有效人声分别为 37.596、31.088、59.852 秒，实际建立 profile 1；这不是识别准确率。

生产匹配结果仅为“声音相近”或“未匹配”，保留时间区间、模型与声纹版本。未匹配不代表确定是他人；声音相近也可能来自本人录音回放。`personal_attribution_allowed` 仍为 false。室内、人声等声音标签同样不能证明是本人现场经历。

自动整理保留会议远端意见、项目讨论、集体决定等有价值上下文，以“会上／讨论中”表达。来源不明的音频不直接成为用户本人承诺、偏好或经历。真实播放、会议及通勤需分别验收，不能以标签分数、合成音频或另一套 ASR 充当真值。

停用声纹会清除当前样本向量、参考向量和匹配记录。原始录音仍遵循原保留策略，既有备份不因停用自动擦除；界面不声称所有副本已删除。

## 本轮真机记录与限制

首轮登记文件实际只有 21.2 秒、VAD 未检出语音，已拒绝；随后卡上发现另一份仍在录制的测试文件，用户手动结束保存。未查明两份文件切换的原因，不把这次失败解释成用户没说话，也没有自动接管或删除另一份文件。之后经只读确认空闲、将卡平放桌面，重新采集的三段均通过质量与跨样本一致性检查，卡上原声自动核对收尾，无需用户手点核对。

151 项 Python 测试与 60 项 Core 自测通过，包括登记授权／设备归属、独立复核、回放仍不赋予个人事实、撤销、队列租约恢复及推理遥测变化的幂等性。iPhone 签名构建和 Mac HeartballLab 构建通过。人工向量测试验证保护逻辑，不用于声纹准确率。

登记后另采集两份**未参与训练**的普通记录，均启用自动转写、标签和整理：

| 真实输入 | 可观测音频 | VAD 选出的粗窗口 | 达到当前声纹阈值 |
| --- | --- | --- | --- |
| 用户单独自然口述 | 86.72 秒 | 7 | 7 |
| 用户操作的视频播放，本人不说话 | 87.36 秒 | 12 | 0 |

这是两个特定条件下的对照计数，不是准确率、完整覆盖率或全天误认率。口述窗口相似度约 0.820–0.927，视频约 0.358–0.582；阈值 0.78 暂为候选门槛。原声自动下载并完成身份、大小和字节对齐；实时流末尾分别少 160 字节（口述，80 毫秒）与 40 字节（视频，20 毫秒），卡上原声已保留，极短尾段语义修复仍标为待复核，不能声称零丢样。

视频在盲测前未设置背景来源。声音标签仍以人声／室内为主，未可靠检出设备播放；自动事件识别为赛事评论讨论，来源仍未知，未形成个人事实或主动建议。随后依据用户实际操作，将这两份文字记录标成背景播放，旧版本保留历史、重新整理文字，不重调 ASR。这个后标注不计为自动来源分类成功。

实测还发现模型给一个 60 秒批次加上“约60分钟的语音转写”的错误前言。r10 在摘要提示词中禁止根据分包猜时长，并移除无原文依据的特定录音时长前言；原话中真实提到的午饭、会议时长保留。重新整理后的当前摘要已无错误前言，原始错误保留历史。活动归集遗漏事项时补充缺失编号反馈，校验不放宽。

全部录音结束后重启声音 worker：11 项任务、13 份观察、profile 1 及 26 份逐字稿均保留，没有重复 ASR。主服务待队列空闲、备份验证后更新 r10，旧 r9 容器停止保留，其他容器不变。此次真实对照新增四次批次 ASR，登记本身未调用 ASR。

已有用户确认的 59.28 秒真实会议片段曾实际运行模型，标签包含人声／室内／独白；会议上下文不因声纹未匹配而自动丢弃。该证据不能验收会议说话人归属或场景分类准确性。本轮没有重传整段历史会议。用户明确当前没有通勤实录，留待现场验证；本人声音回放、远距离、重叠说话及全天长时间分类仍未验收。原声、正文、特征及私有诊断保留在忽略的 `.build` 或个人云端数据卷中。脱敏结果见 [validation](validation/xinlika-allday-voice-2026-10-21/result.json)。
