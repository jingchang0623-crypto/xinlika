## 提炼与展示的共同契约

录音一分钟封批只是传输／ASR 单位，不是事件边界。同一具体问题的追问、方法、例子、回应和效果一起提炼；不相关的对象或目标分别成事。同一会议可以有多个完整事件，也不能为了少几张卡而把整场聚餐压成空泛的一个活动。

有明确操作、现象、限制的短反馈需要保留，即使没有待办、产品全称或长篇描述。无可定位对象的残句、孤立数字、语气词等，先判断是否帮助理解邻近事件；无独立意义时保留为带来源的 fragments，不删除原文，也不给它另起首页标题。

新增的 `complete_events` 契约要求全部原文片段恰好归属一次：事件引用或明确残句。不能用开头一句引用代表整份转写已处理。服务端校验来源版本、授权、缺失与重复，事务失败不部分写入。该校验能防止漏分配，**不能证明模型没有把有价值的反馈误判为残句**，后者仍需真实原文复核。

每个事件携带内部准入理由、内容分类及 `compact`／`summary` 展示选择。分类和卡片大小不能由来源数量、时长或字数代替。首页不展示内部准入理由、来源句柄和校验过程。重点仍独立处理，不被普通记录吞并。

服务端日视图返回唯一 `timeline`；两端直接显示同一事件身份和顺序。活动分组仍可作背景／详情，不再替代首页事件。日期以录制时间选取，客户端切日不会把旧日期结果显示在新日期标题下。`start_local`／`end_local` 是来源时间包络，明确标为 `observed_source_envelope`，不冒充逐字时间。

## 新的同一天比较输入与现状

冻结的是 **2026-10-21 已有且获准处理的普通转写**，包括会议、聚餐及前后内容，不是整整 24 小时音频覆盖。排除重点重叠、无文字／被替代来源和未验证测试来源；按来源 ID 与版本去重，冲突不静默覆盖。旧模型标题、摘要与记忆不输入，人工关系标签只用于事后评估。

| 输入 | 值 |
|---|---|

| 原文字符 | 15,772 |
| 可引用原文片段 | 774 |
| 输入 SHA-256 | `01e2b40aaf75e18ee9a7e840b1ec2f7905771f2133c5d8183d0c10a391d3842b` |
| ASR 新任务／调用 | 0 |
| 模型 | 两者均为当前配置的 `doubao-seed-2.1-pro` |

沿用已固定的 Hermes 原生 `AIAgent`、官方 DeepSeek Harness SDK 和同一领域 MCP；不是两个接口别名。版本信息与上轮数据见 [原生适配记录](xinlika-agent-adapter-2026-10-23.md)。此前 114 份来源的比较和已知漏关联／短反馈失败仍保留，不能替代本轮 131 份来源的验收。

网络恢复回复后的原生重试结果：Hermes 约 67.79 秒、3 次传输失败；DeepSeek Harness 约 27.64 秒、1 次传输失败。均没有提交回执或返回可核验 usage。随后连接检查仍为 TLS 握手超时；直连、HTTP／SOCKS 代理及既有 SSH 通道此前也未连通。没有更改系统代理、节点、TLS 校验或线上服务。**不能评价本轮归并、主题关联、短反馈与残句结果；不能把已知 tokens 为 0 写成成本为零。**

新增比较脚本把失败运行的质量项标为未评分，避免空结果被误算成“不同事项分开通过”。成功后另外核对提交中的片段分配，并生成仅在本机 `.build` 的双栏原文复核页。来源分配完整和项目回归锚点通过都不等于人工准确率；卡片数量、模型一致性也不是质量分数。
