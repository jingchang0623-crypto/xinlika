# Personal Agent 处理循环与服务端 r4

本轮参考 Personal Agent 的行为设定和实际运行循环，而非记忆组件：Omi 的介入判断／生成／复核，OpenClaw 的持久观察任务，Hermes 的分层角色与上下文。固定版本与源文件见 [来源和取舍](../prompts/personal-agent/SOURCES.md)。复用现有 OpenAI SDK、LangGraph 和 SQLite，不另换框架。

## 已接入的工作循环

音频仍默认 60 秒、最大 300 秒封批，ASR 和事件整理复用原链路。新的 `personal_analysis` 作业独立于上传：每五分钟合并观察记录、事件、主题、用户纠正和偏好变化，无变化不调用模型。升级时以当前账本为基线，不把旧历史重新发送一遍。

1. **observe**：理解当前处境、明确目标和新变化，结合相关旧记录、最近提醒和待观察线索，默认静默。
2. **respond**：有具体价值时给一条简短反馈，说明变化如何影响下一步，引用当前证据。
3. **review**：独立拒绝泛泛建议、复述、重复、误归属、忽视更正／完成状态及把旧录音当刚发生。
4. **publish**：落盘前重查权限、证据版本及用户反馈，进入已有 Agent 页“主动反馈”，使用原两端同步协议。

静默时跳过后两次模型调用，可保留带引用的待观察线索。线索不是事实，引用失效即不再带入。节点有持久检查点，复核失败重试接续，不重转写；下一分钟录音到达本身不会反复作废当前分析。默认十五分钟反馈冷却、滚动 24 小时最多六条。已关闭提醒参与去重，“少提醒这类事”保存偏好，纠正使旧建议失效。

角色和提示词：[contract](../prompts/personal-agent/contract.zh-CN.md)、[observe](../prompts/personal-agent/observe.zh-CN.md)、[respond](../prompts/personal-agent/respond.zh-CN.md)、[review](../prompts/personal-agent/review.zh-CN.md)。版本及完整运行提示词 SHA-256 进入私有上下文。目标只能来自明确表达及更正，模型不能凭录音扩张权限或执行外部动作。

普通记录不要求逐条确认。多人会议不默认属于用户本人。背景播放／测试不进入主动个人分析；来源未辨录音可以理解具体事项，但只以“录音中的讨论”反馈，不升级为用户经历、承诺或画像。服务端额外拦截这类反馈的直接个人归属措辞；语言检查不能替代可靠说话人识别和质量评估。

录制时间用于理解事项；现在的时间只用于时效和反馈预算。全文索引帮助召回旧证据，摆脱 UI 最近预览上限；它是词法检索，不声称实现向量语义召回，也不是 Personal Agent 本身。

## 存储与恢复

保留 WAL／FULL、原始封批音频、哈希、幂等作业和纠正历史。`heartball_backup.py` 提供 SQLite 在线一致快照＋封存音频对象，按 SHA-256 去重及复核；恢复只允许新目录，重定位路径，不覆盖在线空间。

正式数据已做一次本机异地副本与隔离恢复：25 个封存对象，22 个批次和 29 条文档，逐批哈希及数据库完整性检查通过。凭据／配置需独立挂回；未封存的在途原声及模型检查点缓存不作为完整恢复承诺。

容器启动 30 秒后备份一次，之后每六小时在线快照，私有状态 `/data/backups/status.json`；r4 首轮自动备份成功。可用空间少于 512 MiB 拒绝新备份，不删除旧录音或快照。**自动异机备份、保留期和容量告警尚未配置**；本轮本机副本是一次实测，当前仍为单机单用户服务。

## CB08 常开方式

录音卡独立持续录，手机按可连接情况接收，服务端独立处理。App 不能被假定能够唤醒已停止广播的待机硬件。沿用明确开始后持续录音、断连保持卡录、同文件恢复和保存后自动补齐；不自动停止、重启或切换低功耗模式。

已有充电长测为同文件 **3 小时 20 分钟**，不是无充电续航或全天运行认证。长期充电、充拔电边界、电量耗尽后恢复仍需真机验收。本轮未新增录音、改设备设置或触碰手机待传数据。
