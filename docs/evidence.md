# 截至 2026-10-23 的实测与限制

此页是 10 月 20–23 日开发会话与验证报告的脱敏提炼。原声、逐字稿、声纹、模型响应、设备身份和云端地址均未发布。外部读者可以复现公开控制测试；因原始私人样本未开放，下列硬件和内容结果属于维护者的开发记录，不是可独立复现的公开基准。

| 项目 | 已观察到什么 | 不能推出什么 |
|---|---|---|
| Mac 充电长测 | 同文件约 3 小时 20 分钟；一次断连后接回后续流，断连期间约 5.2 秒未自动补发 | 不是电池续航，也不是跨文件无缝连续 |
| CB08 按键 | 实测亮屏保存手势结束全局录音；软件重点可独立结束 | 不能把机身保存键当成不间断重点键 |
| iPhone 锁屏与云端 | 锁屏接收、实际转写；服务中断 75 秒后补传；双端纠正同步 | 不等于系统强杀后恢复或整天可靠 |
| 同文件推流恢复 | 先前失败后，厂商 `01 01` 接流在 CB08/V1.0.0 两轮范围往返中恢复原文件后续流，包含 App 后台 | 其他固件、连续多次往返未验收；断连期间仍有漏采 |
| 原声归档与修复 | 完整文件大小、结束码、哈希和唯一字节对齐；只为缺口生成补处理 | 严格解码不证明零丢样或逐字准确；20–100ms 等短尾边界仍可能待语义复核 |
| 物理续段 | 找回两份约 3 小时 / 1 小时 38 分文件；280 个补处理批次完成；原有 408 个 ASR 任务未重跑 | 约 17:39–19:53 仍未找到正面覆盖证据，不能当作静音 |
| 声纹对照 | 安静口述 7 个窗口达到阈值；视频 12 个窗口未达到 | 不是准确率；餐桌 615 个粗窗口仅 2 个达到阈值，泛化明显不足 |
| 聚餐内容 | 活动约 22:19–23:15，29 个子事项折叠；抽查可回到原句和录制日期 | 边界有用户场景辅助；未逐条听审，不是自动活动识别通过 |
| 首页密度 | 一个真实日期 270 个普通子事项和两段重点按规则呈现为 31 行 | 卡片变少不是语义正确；原文与有效事项不能为压数而删除 |
| 来源修复 | 多段原句引用、可逆局部拆分和独立审核已实现；只应用核对通过的局部修复 | 全量历史自动重整仍未通过；失败候选不覆盖原投影 |
| 主动分析 | 实际模型在授权真实文字上运行并静默，引用有效 | 静默正确不等于已验证长期有用建议或“成长教练” |

早期 iPhone 0.3.0/0.3.2 文档中的“断连后无法恢复推流”已由后续 0.3.4 的特定条件实测更新，不能当作最新总体结论。早期“一个文件只能三小时”也被同文件 3 小时 20 分钟长测修正；后来观察到部分文件约三小时续段，两者都应保留条件。

最新原项目记录为 iPhone 0.3.7（25）、共享服务 r26；这些是私有开发部署版本，**不等于本公开仓库 v0.1.0 包含相应客户端**。当前首发后端从这份工作树的新增 Python 模块提取，发布验证另记于 [release-validation](release-validation.md)。

我们尚未测得：整体 CER/WER、全天无损覆盖率、无充电续航、通勤分类可靠性、本人声音回放误认率、完整月成本或主动建议长期价值。因此不发布“100%准确”“24小时无损”“免费平替”“成本降低90%”等数字。

后续 v0.2.0 已经权利人确认，将原生客户端以 GPL-3.0-only 纳入；新公开构建证据见 [native-validation](native-validation.md)，配置与构建见 [完整应用](full-app.md)。它不改变上表硬件及内容质量边界。
